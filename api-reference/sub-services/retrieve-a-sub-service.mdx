---
title: "Retrieve a sub-service"
description: "Retrieves a single sub-service by ID. Requires the services.read scope."
openapi: "GET /sub-services/{id}"
---

Returns one priced item.

**Required scope:** `services.read`

**Base URL:** `https://mex-pet-app.vercel.app/api/v1`

## Example

```bash
curl "https://mex-pet-app.vercel.app/api/v1/sub-services/sub_4c0fcd" \
  -H "Authorization: Bearer mxp_live_your_token_here"
```

## Response `200`

```json
{
  "id": "sub_4c0fcd",
  "object": "sub_service",
  "service_id": "svc_ff6a7b",
  "name": "Dog Boarding (5 x 5)",
  "description": "Overnight stay in a 5x5 suite.",
  "price": 24,
  "duration_minutes": null,
  "sort_order": 0,
  "is_active": true,
  "pricing_model": "fixed",
  "unit_label": null,
  "created_at": "2026-01-01T00:00:00.000Z"
}
```

## Errors

| Status | Type | When |
| --- | --- | --- |
| `404` | `not_found` | No sub-service with that id in your business |
| `403` | `invalid_request_error` | Token lacks the `services.read` scope |

<Note>
  A sub-service belonging to another ranch returns `404`, not `403`. Every lookup is scoped to the token's business, so an id outside it simply does not exist as far as your token is concerned.
</Note>
